## 二、最关键发现

### 2.1 Phaser3 现代重写版（含 80+ 份机制逆向文档 + 结构化数值表）

`kagami-kasumi/zaomengxiyou3-zaixutiantingpian-phaser-version`——与本项目几乎同构的工程（Phaser3+TS+Vite、AI 多 agent 协作、"逆向与实现分离"哲学），其对《再续天庭》（造3 同人改版）的逆向产出可直接作为机制字典：

- `docs/reverse-engineering/` 80+ 索引：combat-rules（互伤规则）、drops（掉落）、equipment（装备）、pets、monsters、levels、skills-input、crafting（合成）、shop、save-slots……每条结论都带 AS3 反编译源码证据链
- `docs/reverse-engineering/reference/` 结构化数据：`equipment-data-catalog-1.1.json`（1.9MB 全装备+Schema）、`hero-progression-catalog-1.1.json`（角色成长）、`crafting-recipes-1.1.json`（配方）、CSV 版装备/宝石/掉落表、社区 1.0 数值 xlsx

**互伤核心链路**（来自其 combat-rules-index）：
1. 攻击方 `newAttackId()` 生成唯一攻击实例并切 hit 动作
2. 动作帧创建 `BaseBullet` 子类，`setRole(source)` 记录来源与攻击编号
3. 命中配置存于 `attackBackInfoDict[action]`：命中次数、命中间隔、攻击类型、击退、保护分
4. `checkAttack()` 按阵营选目标数组；目标侧 `beAttackIdArray` 做同攻击去重
5. 受击方一次性完成 碰撞→闪避→伤害→防御→击退→扣血→受击反馈→死亡

> 对照《造梦纪》现状：我们的 `DamageInfo{amount,isCrit,fromX,knockbackX,hitstopMs}` + `HitQuery` 已覆盖其中大半；**缺口是"多段命中/命中间隔"与"受击保护(短暂无敌)"的配置化**——革新重构时应在契约层补上。

### 2.2 存档格式逆向（造3/再续天庭）

来自 save-transformer 的 `结论.md` + jbji 工具（MIT）：

- 解密流水线：自定义 Base64（变体字母表）→ XOR 0x5A → Zlib（1~2 轮）→ 剥 AMF3 String 头
- 物品行：**28 字段管道分隔**——品级/名称/代码/槽位(zbwq武器·zbfj防具·zbsp饰品·zbfb法宝·zbsz时装)/角色限制/品质文本/**品质十六进制色**/属性1~9/强化等级/法宝成长开关×5+值×2/堆叠数量/获得日期
- 宠物行 `petSave`：管道分隔数值 + `~` 分隔技能代码
- CSDN CE 逆向佐证：造4 血量等属性为 **double 双浮点**，属性在内存连续排布

> 对照《造梦纪》现状：我们的存档是 localStorage JSON + 版本号（方向正确）；品质色板、堆叠数量、获得日期、槽位分类可作为 v3 存档字段设计参考。
