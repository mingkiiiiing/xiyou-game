## 2. 压力测试数据（逻辑层）

| 场景 | 结果 |
|---|---|
| 波次系统：100 怪 + Boss 全流程 | 12,737,365 次编排调用 / 2,401ms（含每波 600ms 刻意节奏停顿）→ 单次编排调用 ≈ 0.19µs |
| 伤害公式吞吐 | 200,000 次 / 16.5ms → ≈ 82ns/次 |
| 掉落→穿戴→属性聚合 | 10,000 轮 / 98.9ms → ≈ 0.0099ms/轮 |
| 单帧逻辑预算（100 怪在场） | p50 0.008ms · p95 0.018ms · p99 0.033ms → **p95 仅占 60fps 单帧预算的 0.1%** |

**边界声明**：以上为**逻辑层**开销，不含渲染（Graphics/WebGL）。渲染帧时间必须在浏览器中实测，见 §5。

## 4. 发现的问题与修复（关键交付）

冒烟与压力测试共发现 6 个问题，**全部已修复并回归验证**：

| # | 级别 | 问题 | 修复 |
|---|---|---|---|
| 1 | **P0** | `recalcStats` 传入 `Equipment` 实例时静默产出 `undefined` 并崩溃（接口陷阱，压力测试场景3实测触发） | `EquipmentInput` 鸭子类型识别 `.all()`，接受实例/槽位记录/数组三种形态 |
| 2 | **P1** | 品质基础属性倍率（docs/02：白1.0~红2.2）**未实现**，品质只影响词条数 | 新增 `qualityMult` 字段 + `QUALITY_STAT_MULT` 表，在 `itemStats` 聚合时生效（向后兼容：省略按 1.0） |
| 3 | **P1** | 宝石表双份定义（E 内置 `gem_atk_1`/`stat` vs D 的 `gems.json`/`attr`），改配置不生效 | `gems.json` 收敛为**唯一数据源**，`data.ts` 配置驱动 + `attr→stat` 适配，删除内置表 |
| 4 | **P2** | 词条数量表与 docs/02 不一致（1/1/2/3/4 vs 0/1/2/3/4/5） | 对齐 docs/02 为 0/1/2/3/4/5 |
| 5 | **P2** | 伤害公式内嵌于需 pixi 的类中，测试只能独立复刻 → 漂移风险 | 抽离为 `src/game/damage.ts` headless 纯函数，玩家/敌人/测试三方共用 |
| 6 | **P2** | 敌人暴击硬编码 5%/×1.5，未走配置 | `EnemyBase` 改为可配置 `critRate`/`critDmg` 字段，统一走公式模块 |
