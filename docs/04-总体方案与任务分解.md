# 总体方案：从 M1 到「完整对标造梦西游4」

> 本文是总纲：把整个游戏拆成 6 个**可并行推进的大任务（BT）**，每个含目标 / 角色 / 产出 / 依赖 / 验收。
> 单任务内部的详细工作单见 `docs/tasks/BIGTASK-*.md`，执行时再拆成子任务分派给不同角色。

## 0. 现状盘点（2026-09-12）

**已完成且验证**：框架(A)、战斗角色(B)、敌人与Boss(C)、数值表(D)、装备养成(E，81项测试)、关卡流程存档(F)、特效音频(G)、M0 骨架

**关键判断**：七个模块各自能跑，但**彼此尚未互联**——F 的关卡流程仍在用 M0 灰盒 `Player`，掉落只是结算面板上的一行文字，装备属性、特效、音效都没接进战斗。

> 因此第一大任务是**集成**，不是继续堆新功能。先让"打怪→掉落→变强"这个核心循环真正闭合，后续所有内容扩展才有立足点。

## 3. 各大大任务详述

### BT-1 集成与可玩闭环
- **目标**：让 B/C/D/E/F/G 真正协同，形成"进游戏 → 选角 → 选关 → 战斗（带装备属性）→ 怪死掉落实体 → 走过去拾取 → 结算变强 → 再战"的完整闭环，并用自动化测试守住成果。
- **角色**：集成主管、战斗/玩法/表现程序、数值/关卡策划、测试 QA
- **核心产出**：集成主场景、战斗编排器、装备数值桥接、地面掉落物与拾取、战斗表现层、冒烟测试、压力测试、平衡报告
- **依赖**：B~G 已完成
- **验收**：`?scene=game` 全流程可玩且 0 console error；装备穿上后战力变化可观测；冒烟测试全绿；100 怪 + 500 弹幕下 ≥50fps

### BT-2 美术与表现升级
- **目标**：从灰盒进化为真美术——角色精灵动画、多层视差场景、正式 UI、升级版特效与音频。
- **角色**：2D 美术、动画/特效美术、音频、表现程序、UI/UX
- **核心产出**：资源加载管线（图集/切图）、`AnimationController` 动画状态机、角色与场景美术资源、UI 皮肤、BGM 与音效库
- **依赖**：BT-1（美术素材设计**不依赖代码**，可提前开工）
- **验收**：角色有跑/跳/攻/受击动画；场景 3 层视差；UI 呈西游国风；无占位色块残留

### BT-3 战斗系统深化
- **目标**：手感与战斗深度对标造梦4——技能树、连招指令、闪避翻滚、韧性硬直、多样化怪物行为。
- **角色**：战斗程序、玩法程序、数值策划、关卡策划
- **核心产出**：技能树与技能升级、连招指令表、闪避与无敌帧、韧性/硬直系统、怪物 AI 行为库（10+）、Boss 阶段脚本
- **依赖**：BT-1
- **验收**：技能可升级；闪避有无敌帧；Boss 有 5+ 招式且阶段转换有演出

### BT-4 养成与数值闭环
- **目标**：完整养成经济——装备全流程、强化、宝石、洗练/合成、技能升级、商店、药水。
- **角色**：系统策划、数值策划、玩法程序、UI/UX
- **核心产出**：正式背包/装备/强化/宝石 UI、商店与货币体系、药水消耗品、装备合成与洗练、经济数值表
- **依赖**：BT-1
- **验收**：掉落→穿戴→强化→战力提升闭环成立；商店可买卖；30 分钟体验有明确成长感

### BT-5 内容与关卡扩展
- **目标**：内容量达到可连续游玩数小时——3 角色、第一章 5 关 + 东海龙宫、精英/噩梦难度、更多 Boss。
- **角色**：关卡策划、数值策划、美术、战斗程序、关卡程序
- **核心产出**：3 个可用角色、花果山 5 关 + 东海龙宫章节、精英/噩梦难度系统、12+ 怪物、4+ Boss、剧情演出
- **依赖**：BT-2、BT-3
- **验收**：三角色手感各异；通关第一章约 1 小时；精英/噩梦有独立掉落与挑战性

### BT-6 长线系统与发布
- **目标**：留存与上线——宠物/坐骑/时装/日常/成就、性能优化、多端打包。
- **角色**：系统策划、玩法程序、存档/后端程序、测试 QA、发布工程
- **核心产出**：宠物/坐骑系统、日常与成就、云存档、性能优化报告、微信小游戏/桌面端打包
- **依赖**：BT-4、BT-5
- **验收**：打包产物可运行；长时游玩无内存泄漏；留存目标可达成

## 4. 并行推进策略

1. **同一时刻最多 2~3 个并行 agent**（本账户速率限制实测结论，见项目记忆）——超限会导致 agent 中途夭折
2. 派发前把子任务写成**自包含工作单**（目标+接口契约+禁止区+验收），agent 中断后可凭卡续做
3. 大任务内先定**接口契约**（由集成主管落成 stub/类型），再并行填充实现，避免互相等待
4. 每个大任务收尾固定流程：**审查 → 联调 → 压力测试 → 修问题 → 更新任务卡**
