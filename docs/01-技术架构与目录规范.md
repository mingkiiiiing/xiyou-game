# 技术架构与目录规范（多会话并行必读）

## 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言/构建 | TypeScript + Vite | 全文本化，AI 协作与并行效率最高，秒级热更新 |
| 渲染 | PixiJS v8 | 只管渲染不管玩法，动作手感完全自控；WebGL 性能足够 |
| 数据 | JSON 配置表（`src/config/`） | 改数值不改代码；是"造梦类"游戏的核心架构 |
| 存档 | localStorage（带版本号） | M2 实现，后续可平滑换后端 |
| 依赖策略 | **零新增依赖**（并行冲刺期间禁 npm install） | 避免 package.json 冲突 |

## 并行协作规则（硬性）

1. **目录隔离**：每个任务只写自己任务卡指定的目录；可以 import 任何文件，但禁止修改冻结区
2. **冻结区**（冲刺期间）：`src/core/`、`src/shared/`、`src/scenes/BattleScene.ts`、`src/scenes/entities/`、`package.json`、`tsconfig.json`、`index.html`、`scripts/`（D 除外）、`src/config/`（D 除外）
3. **需要新公共类型**：先在自己模块内定义导出，集成时由主会话合并进 `src/shared/types.ts`
4. **演示场景自动发现**（无中央登记文件，避免多人改同一文件）：
   ```ts
   // src/scenes/demos/taskB.ts
   import type { Game } from '../../core/Game';
   import { Scene } from '../../core/Scene';
   export const sceneKey = 'taskB';
   export function createScene(game: Game): Scene { /* ... */ return scene; }
   ```
   浏览器用 `?scene=taskB` 访问；main.ts 通过 `import.meta.glob` 自动发现
5. **完成前**：`npx tsc --noEmit` 必须对本任务目录零错误（并行期不要跑 vite build，避免 dist/ 冲突；全量构建由主会话集成时执行）
6. **素材**：一律 Graphics 灰盒/色块，禁止引入任何二进制图片音频（后期统一替换）
7. **任务完成协议**：改任务卡状态为 `已完成(日期)`，在卡末尾追加「完成报告」（文件清单/验收结果/遗留问题）

## 核心契约速览（详见 `src/shared/types.ts`）

- `BattleStats` 战斗属性；`DamageInfo` 伤害事件载荷（含击退/顿帧）
- `HitboxDef` 攻击判定框（相对脚底中心，facing=-1 时 offsetX 自动镜像）；`HitQuery` 场景命中查询回调
- `SkillDef` 技能（CD/耗蓝/倍率/判定框/位移，配置驱动）；`Damageable` 可受击实体接口
- `MonsterDef` / `ItemDef` / `LevelDef` 怪物/装备/关卡表结构
- `GameEvents` 全局事件：`damage` / `enemy-died` / `level-complete`，系统间只通过事件 + 契约类型交互
